# 一页设计说明

## 项目目标

`MiniPal` 是一个桌宠风格的最小可用桌面 AI 机器人。它能够接收按钮和距离传感器输入，使用 ESP32 进行实时状态管理，并控制舵机、LED 和蜂鸣器给出反馈；同时，主机侧 Python 程序可通过本地规则或云端 API 提供一个最简单的 AI 动作决策能力。

在没有实体硬件的情况下，项目使用浏览器仿真器展示同一套输入、状态机、AI 决策和输出反馈闭环。

## 关键设计决策

### 1. 分层控制

- 实时闭环交给 ESP32
- 高层策略交给主机 Python

这样可以兼顾稳定性和“AI 接入”要求，也避免把网络延迟直接带入底层控制。

### 2. 状态机而不是单次触发

系统包含五个状态：

- `IDLE`
- `WAKE`
- `TRACK`
- `ALERT`
- `COOLDOWN`

按钮中断只触发事件，真正的决策和输出都放在主循环中完成，结构清晰，便于调试。

### 3. 结构优先考虑稳定和装配

- 舵机放在上层，便于做“头部动作”
- 电池和主板放在下层，降低重心
- 传感器位于前脸中央，并直接形成桌宠“眼睛”

外壳尺寸默认约为 `100 x 90 x 70 mm`，壁厚 `3 mm`，适合 FDM 3D 打印。

## 工程风险

最主要的风险来自：

- 舵机供电导致的电压下陷
- 距离传感器噪声
- 打印孔位和支撑面失败

因此本设计从一开始就把：

- 电源分离
- 传感器滤波
- 打印公差预留

作为核心工程约束。

## AI 接入方式

默认采用“本地规则 + 可选云端”的双模方案：

- 本地规则：低延迟、低成本、稳定
- 云端 API：展示更强的 AI 可扩展性

这个选择符合课程作业对“AI 落地到设备上”的要求，同时风险可控。

## 仿真验证

浏览器仿真器提供按钮输入、距离滑块、状态机显示、舵机角度、LED 状态、蜂鸣器状态和串口日志，用于证明设计不是单纯概念图，而是可以按控制逻辑运行的系统模型。
